## 1. Delivered

| Requirement | Implementation |
|---|---|
| Responsive application shell | `AppShell`: header (workspace label, notifications, account menu), sidebar on ≥ md, menu disclosure on mobile, skip link, landmarks |

| Distinct experiences | **Client portal** (`/portal…`), **Accounting staff portal** (`/staff…`), **Reviewer/manager workspace** (`/review…`), **Firm administration** (`/admin…`), plus account pages and a home router (`/app`) |
| Demo data | Only on documents, requests, work queue and review queue previews. Synthetic, inside a "DEMO DATA" notice, never stored, hidden in production. |
| Route-access tests | Unit (policy matrix + navigation consistency) and **live** (production build, real sessions, direct URLs); see §3 |

## 3. Tests actually executed (2026-10-10)

| Suite | Environment | Result |
|---|---|---|
| `npm run check` (format, lint, typecheck, unit + DB tests, build, bundle secret scan) | Local | **Pass:** 12 files, **149 tests**; secret scan OK (20 files) |
| Route policy unit tests (`src/lib/access/route-policy.test.ts`) | Local | **44/44**: exact allowed-route set for 10 personas; every nav item and tab is allowed; every allowed area is in the nav; home is allowed; path matching rejects malformed ids and traversal |
| Open-redirect tests (`safeNextPath`) | Local | **8/8** |
| DB access-summary tests | PGlite | **3/3** (assigned only; managers all; none without MFA) |
| **Live route-access suite** (`npm run test:routes`) | **Production build (`next start`) + dev Supabase, real sessions** | **23/23 pass** |
| Phase 3 regression: live cross-tenant API suite | Dev Supabase | **32/32 pass** |
| Cleanup | Dev Supabase | 0 clients, 0 users, 0 firm memberships left |

What the live route suite proves, over **25 URLs × 9 signed-in personas** (firm admin, manager, reviewer, accountant, client owner/staff/viewer, another tenant's owner, no-role user):
- **Direct URLs with real cookies:** the server's answer (allowed / access-denied / not-found / redirect) equals the policy for **every** URL and persona.
- **Hard-coded critical cases** (independent of the policy):
  - client A users get *not-found* for client B URLs;
  - staff get *not-found* for unassigned clients;
  - the firm admin is denied client records;
  - a manager is denied `/admin/users`.
- **No session:** every protected URL gets **307 → /login?next=…**.
- **Staff session without MFA:** redirected to `/mfa`. **Disabled account:** redirected to `/account-disabled`.
- **Rendered navigation:** the links in the HTML are **exactly** the policy's routes, and every link opens as allowed.
- **No leakage:** client B's name is not present in any response client A's owner receives for B's URLs; the firm admin's denied page does not contain client A's contact data.

**Mutation check:** the server guard was deliberately broken to allow `/staff/clients/*` for everyone, and the app rebuilt.
- **7 tests failed**, as intended.
- Some of the broken requests still returned not-found because **RLS independently hid the data** (defense in depth).
- The guard was restored, the app rebuilt, and all suites re-run green.

## 4. Issues found during this phase

- **Test classification bug (not an access bug).** Next.js embeds the app-wide not-found boundary in every page's payload, so its marker appeared on allowed pages too. The root not-found page now uses its own marker (`unknown-page`). Found by the live suite on its first run; fixed and re-verified.
- **Lint:** the mobile menu reset state inside an effect (cascading renders). Rewritten without an effect.
